# Application Lifecycle Management (ALM) : Stages

ALM regards the entire life of an application from business requirement to retirement. 
In software and cloud engineering, Day 0, Day 1, and Day 2 
represent the three main stages of the that lifecycle.

## Day 0: Planning and Design 

- Architecture: Deciding how the software and system will look, picking tools, and choosing cloud or local hardware. 
- Strategy: Setting up security rules, compliance guides, and making sure the budget and team skills match the goal. 
- Goal: Figuring out what to build and how it should run before writing any code.

## Day 1: Deployment and Installation 

- Building: Writing code, setting up testing environments, and running pipelines. 
- Provisioning (Release): Launching the base infrastructure using code templates and installing the software into production for the first time. 
- Goal: Getting the system live and working for users. 

## Day 2: Operations and Maintenance 

- Monitoring: Watching the system live to catch errors, tracking speed, and checking memory or CPU use. 
- Upgrading: Fixing bugs, applying security patches, scaling up capacity, and handling unexpected crashes. 
- Goal: Keeping the live software healthy, secure, and running smoothly over its entire lifespan.

# ALM framework vs Day 0/1/2

## How They Align

* Day 0 Maps to ALM Requirements & Design:
In ALM, this is where business analysts and architects gather requirements, estimate costs, and design the software architecture. [4, 5] 
* Day 1 Maps to ALM Development & Testing:
In ALM, this covers writing code, running automated tests, build management, and final release deployment.
* Day 2 Maps to ALM Operations & Governance:
In ALM, this is the longest phase, focusing on user feedback, application performance monitoring, bug fixes, optimization, and eventual decommissioning.

## Key Differences

* ALM is a software-governance framework. It connects business goals, project management, code repositories, and QA testing.
* **Day 0, 1, 2 is an infrastructure and DevOps perspective**. It focuses heavily on automation, system stability, cloud provisioning, and long-term maintenance. [6, 7, 8, 9, 10]
